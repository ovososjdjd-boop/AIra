## 0. Рамка (откуда взята)

DoD: паритет качества с бейзлайном-стойки при ≥10× меньшей энергии/токен.
CALC-04: бюджет сходится при четырёх опорах: **α≥10** (лит., к измерению),
**s≥0.28 @ acc≥0.95** (изм. 0.343), **a≤0.42**, **w≤0.42** (изм. EXP-13).
CALC-05 уточняет duty: **0.771 (1-й проход) → 0.657 (устойчивое)**.

## 1. Архитектура

```
поток токенов
    │
    ▼
[Маршрутизатор 2D] ──(f ≥ θ(α)  и  N(ctx) ≥ Nmin(α))──► [Полка L0] ──► ответ, цена ~0
    │                                                             ▲
    │ иначе                                                       │ запись (ctx→next)+=1 — ВСЕГДА, O(1)
    ▼                                                             │
[Зона-умение L1] ◄──── обучается ТОЛЬКО на отфильтрованных позициях (novelty-duty)
    │
    ▼
ответ, цена = активные веса (сон) × SRAM-трафик
```

Три органа:

| Орган | Форма v0 | Ключевые числа |
|---|---|---|
| **Маршрутизатор** | правило (f, N): отдать полке если f≥θ и N≥Nmin; иначе веса | α=0.95: (θ=0.90, Nmin=2) → покр. 34.3%@0.957; α=0.97: (θ=0.90, Nmin=5) → 27.9%@0.975 · **заменяет старое θ-only 0.90 правило EXP-15b** (доминирует его по обеим осям) |
| **Полка L0** | каскад ключей c8 (канон EXP-15b, backoff 8→4→1) + **фильтр записи N≥2** | сейчас: 1.11M повторных пар ≈ **10 МБ** (запись 9 Б) вместо 30 МБ сырых; ×30 Kaggle: ~300 МБ (правило S ✓: рост N^0.811 суб-линейно) |
| **Зона-умение** | CharMLP-96 ctx32, PC-химия v3.2 (β0.1-расписание, K1, K2, BB+сторож, freeze 3e-3, σ-δ θ=0.05) | 117k параметров; активность ≤0.42 |

**Найденное CALC-05 инженерное правило (принять в канон): запись в полку N≥2-фильтром — тройная выгода:** память ÷3 (66.6% пар — синглтоны, несущие 22.8% обращений), точность ↑ (N=1 — врётель по CALC-03b), консолидация встроена (N=2 — это и есть «подтверждённый факт»).

## 5. Прогнозы-ставки к прогону H-33 (публикуются ДО пуска)

Рука A: зона-96 + полка-2D (θ=0.90, Nmin=2, запись-фильтром N≥2) + duty-filtered обучение.
Рука B: чистая зона-96 v3.2, тот же поток.
Руки B256/B512 (контроль α): чистые зоны 256/512 той же химии — α-эквивалент
полки: α̂ = P*(ppl_A) / 117k.
Поток M1 (8.1M ids) + valid wikitext2 (live).

| Ставка | Прогноз | Смерть-критерий |
|---|---|---|
| S1 качество | ppl_A ≤ ppl_B × [0.97..1.00] (прецедент EXP-15b −4.5% live) | ppl_A > ppl_B × 1.01 |
| S2 duty | duty₁ ≤ 0.78 (1-я эпоха), → ≤0.66 устойчиво | duty₁ > 0.85 |
| S3 α | α̂ ∈ [10, 25] | α̂ < 3 |
| S4 polish | acc полки на закрытых ≥0.95, покрытие ≥0.30 (live) | acc <0.90 |
| S5 энергопрокси | цена/токен обучения A ≤ B × 0.25; вывода ≤ B × 0.15 | > B × 0.5 |

Прогон целиком ~2×60–90 мин + 2×~15 мин контроли α, звенья 15 мин,
state-страховка, один процесс. **Ждёт визу.**

## 6. Смерть-критерии по компонентам (при разборе отдельно)

- Маршрутизатор: 2D-правило проигрывает θ-only-статистике на гибрид-ppl →
  снять с канона, вернуть EXP-15b форму.
- Полка N≥2-фильтр: потеря покрытия >5 п.п. против сырой на valid → фильтр ✗.
- Duty-фильтрация обучения: ppl_A деградирует >2% относительно обучения-на-всём
  → novelty-duty применять только к энергобюджету, не к градиенту (⏸).
- Полка-память: не влезает в RAM на Kaggle-объёме (>1 ГБ) → переход на
  count-min-sketch (отдельный наряд, ~4 Б/запись, ложноположительность
  маркируем, F1-влияние полки <1 п.п. по расчёту CALC-03-надёжности).
